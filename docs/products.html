Herlan REST API — পণ্য (Products) ও ফিল্টার (Filter)

এই ডকুমেন্টে শুধুমাত্র মোবাইল অ্যাপের পণ্যের তালিকা (product listing), পণ্যের বিস্তারিত (product detail), রিভিউ/প্রশ্ন-উত্তর এবং ফিল্টার (filter) সংক্রান্ত API গুলো আছে। Authentication, Cart, Checkout, Orders ইত্যাদির জন্য index.html দেখুন — সেখান থেকে কোনো কিছু মুছে ফেলা হয়নি, এই ফাইলটি আলাদাভাবে যোগ করা হয়েছে।

দ্রুত টিপ: যদি আপনি শুধু একটা জিনিস মনে রাখতে চান, সেটা হলো — প্রায় সব পণ্যের তালিকা GET /group/products দিয়েই হয়। ব্র্যান্ড পেজ, ক্যাটাগরি পেজ, সার্চ রেজাল্ট, ফিল্টার করা রেজাল্ট — সবকিছুর জন্য একই endpoint ব্যবহার হয়, শুধু প্যারামিটার আলাদা হয়।

Base URL

https://YOUR_DOMAIN/wp-json/herlan/v1

লোকাল (localhost) উদাহরণ:

http://localhost/herlanlive3/wp-json/herlan/v1

Response ফরম্যাট

সফল (success) রেসপন্স সবসময় এই কাঠামোতে আসে:

{
  "success": true,
  "message": "",
  "data": {}
}

এরর (error) হলে WordPress REST-এর স্ট্যান্ডার্ড ফরম্যাটে আসে:

{
  "code": "herlan_error_code",
  "message": "Error message.",
  "data": {
    "status": 400
  }
}

অর্থাৎ, কোড লেখার সময় সবসময় আগে success ফিল্ড চেক করবেন। true হলে data-তে আসল তথ্য পাবেন, false/এরর হলে message ইউজারকে দেখাতে পারবেন।

Product Listing API

এই সেকশনে আছে মূল প্রোডাক্ট লিস্টিং endpoint এবং তার সাথে জড়িত ফিল্টার endpoint গুলো। মোবাইল অ্যাপের প্রতিটি প্রোডাক্ট আর্কাইভ পেজ, ফিল্টার ড্রয়ার, এবং সার্চ স্ক্রিন — সবই এখান থেকে চালিত হয়।

এটি কীভাবে কাজ করে

ওয়েবসাইটের প্রতিটি প্রোডাক্ট লিস্টিং পেজ — সেটা ব্র্যান্ড পেজ হোক, ক্যাটাগরি পেজ হোক, ফিল্টার করা রেজাল্ট হোক, বা সার্চ হোক — সবকিছুই একটামাত্র endpoint দিয়ে সার্ভ হয়:

GET /wp-json/herlan/v1/group/products

মোবাইল অ্যাপকে শুধু দুইটা জিনিস বলতে হয়:

  1. Archive context — ইউজার কোথায় আছে (যেমন: Nior ব্র্যান্ড পেজে, বা Lipstick ক্যাটাগরি পেজে)
  2. Active filters — ইউজার কী কী ফিল্টার সিলেক্ট করেছে (যেমন: skin type = Combination Skin, category = Eyes)

এই endpoint একসাথে রিটার্ন করে: মিলে যাওয়া প্রোডাক্টগুলো, লাইভ কাউন্ট সহ ফিল্টার অপশন, প্রাইস রেঞ্জ, পেজিনেশন, এবং বর্তমান সর্ট (sort) অবস্থা।

ওয়েবসাইট URL → API কল ম্যাপিং

এটাই মোবাইল ডেভেলপারের জন্য সবচেয়ে গুরুত্বপূর্ণ কনসেপ্ট। ওয়েবসাইটের প্রতিটি URL সরাসরি একটা API কলের সাথে ম্যাপ হয়। নিচের টেবিলে সাধারণ কিছু উদাহরণ দেওয়া হলো।

ওয়েবসাইট URLসমতুল্য API কল

গুরুত্বপূর্ণ কথা:

  • /makeup/lip/lipstick/-এর মতো nested (nested) ক্যাটাগরি URL-এর ক্ষেত্রে শুধু সবার শেষের term slug (lipstick) দিলেই হবে — পুরো path দিতে হবে না। WordPress প্রতিটা term-কে ইউনিক slug দিয়ে রাখে।
  • এই endpoint সবসময় চাইল্ড ক্যাটাগরি অটোমেটিক include করে (include_children=true) — তাই প্যারেন্ট ক্যাটাগরি (যেমন makeup) দিলে তার সব চাইল্ড (lip, lipstick, lip-gloss ইত্যাদি) এর প্রোডাক্টও চলে আসবে।
  • ওয়েবসাইটের পুরনো (legacy) query parameter নাম (যেমন ?product-cat=... বা ?_brand=...) সরাসরি পাঠালেও চলবে — API নিজে থেকেই সেগুলো নরমালাইজ করে দেয়। মোবাইল অ্যাপের নাম বদলাতে হয় না।

পুরনো (Legacy) নাম নরমালাইজেশন

ওয়েবসাইটের ফ্রন্টএন্ড কিছু নন-স্ট্যান্ডার্ড query parameter নাম ব্যবহার করে। API উভয় (পুরনো ও নতুন) নাম গ্রহণ করে এবং নিজে থেকেই ঠিক করে নেয়।

Legacy (ওয়েবসাইট স্টাইল)Canonical (নতুন কোডে এটাই ব্যবহার করুন)
_brandfilter_brand
product-catfilter_product_cat
_skin-typefilter_skin-type
_age-rangefilter_age-range
_keywordsfilter_keywords
sort-byorderby

উদাহরণ — এই legacy URL:

/brand/nior/?product-cat=eyebrow,eyes&_skin-type=combination-skin

API-তে যেভাবে normalize হয়:

GET /group/products?context_taxonomy=brand&context_term=nior&filter_product_cat=eyebrow,eyes&filter_skin-type=combination-skin

GET /group/products

একটা paginated (পেজ-ভিত্তিক) প্রোডাক্ট লিস্ট রিটার্ন করে, সাথে লাইভ ফিল্টার কাউন্ট, প্রাইস রেঞ্জ, এক্টিভ ফিল্টার এবং পেজিনেশন। এটাই সব প্রোডাক্ট লিস্টিং স্ক্রিনের মূল (core) endpoint।

Request প্যারামিটার

১. Archive context — ইউজার কোথায় আছে:

ParameterTypeপ্রয়োজনীয়?ব্যাখ্যা
context_taxonomystringনাআর্কাইভের taxonomy slug। এর একটি: product_cat, product_tag, brand, keywords, skin-type, age-range
context_termstringশর্তসাপেক্ষআর্কাইভ term-এর slug। context_taxonomy দিলে এটা বাধ্যতামূলক।

নিয়ম:

  • দুইটাই না দিলে — এটা একটা সাধারণ shop/search লিস্টিং হিসেবে কাজ করবে।
  • context_taxonomy দিলে context_term অবশ্যই দিতে হবে।
  • product_cat-এর ক্ষেত্রে চাইল্ড ক্যাটাগরি সবসময় include হবে।

২. Taxonomy ফিল্টার — ইউজার কী সিলেক্ট করেছে:

ফরম্যাট: filter_{taxonomy}=slug-a,slug-b

Parameterউদাহরণব্যাখ্যা
filter_brandfilter_brand=nior,herlanএক বা একাধিক ব্র্যান্ড slug দিয়ে ফিল্টার
filter_product_catfilter_product_cat=eyes,eyebrowএক বা একাধিক ক্যাটাগরি slug দিয়ে ফিল্টার
filter_skin-typefilter_skin-type=combination-skinস্কিন টাইপ দিয়ে ফিল্টার
filter_age-rangefilter_age-range=25-35বয়সের রেঞ্জ দিয়ে ফিল্টার
filter_keywordsfilter_keywords=paraben-freeকীওয়ার্ড দিয়ে ফিল্টার
filter_pa_colorsfilter_pa_colors=vintage-vibesরং (color attribute) দিয়ে ফিল্টার
filter_pa_sizefilter_pa_size=100mlসাইজ attribute দিয়ে ফিল্টার
filter_pa_variantfilter_pa_variant=aloeভ্যারিয়েন্ট attribute দিয়ে ফিল্টার

WooCommerce-এ রেজিস্টার করা যেকোনো pa_* attribute কোনো কোড পরিবর্তন ছাড়াই সাপোর্ট হয়।

৩. Filter operator — একাধিক ভ্যালু কীভাবে মেলাবে:

Parameterডিফল্টভ্যালুব্যাখ্যা
filter_operator_{taxonomy}inin, and, not_inin = যেকোনো একটা সিলেক্টেড term মিললেই হবে, and = সবগুলো term-ই মিলতে হবে, not_in = বাদ দিন

উদাহরণ: filter_operator_brand=and — প্রোডাক্টকে অবশ্যই সিলেক্ট করা সব ব্র্যান্ডের অন্তর্ভুক্ত হতে হবে।

৭. Include flags — রেসপন্সে কী কী থাকবে তা নিয়ন্ত্রণ করে:

ParameterTypeডিফল্টব্যাখ্যা
include_productsboolean1রেসপন্সে প্রোডাক্ট লিস্ট থাকবে কিনা

include_paginationboolean1পেজিনেশন ব্লক থাকবে কিনা
টিপ: সাধারণ প্রোডাক্ট লিস্টিং বা পেজিনেশন কলের জন্য include_filters=0 (ডিফল্ট) রাখুন। ইউজার যখন ফিল্টার ড্রয়ার ওপেন করে, শুধু তখনই include_filters=1 পাঠান — কারণ এতে সব taxonomy জুড়ে লাইভ কাউন্ট হিসাব করতে হয়, যা একটু ভারী কাজ।

GET /taxonomies

এক কলেই সব ফিল্টারযোগ্য প্রোডাক্ট taxonomy ও তাদের term রিটার্ন করে। ফিল্টার UI (dropdown, checkbox, chip) পপুলেট করতে এবং ইউজার একটা term সিলেক্ট করলে GET /group/products-এ কোন filter_* প্যারামিটার পাঠাতে হবে তা জানতে এটা ব্যবহার করুন।

Taxonomy রেসপন্সের ফিল্ড: taxonomy (internal slug), label (মানুষের পড়ার নাম), filter_key (GET /group/products-এ ব্যবহার করার query param নাম), hierarchical (parent/child আছে কিনা), terms (এই taxonomy-র term-সমূহ)।

Term ফিল্ড: id, name, slug (ফিল্টার করার সময় এই ভ্যালুই ব্যবহার করুন), count, parent (0 = top-level), image, color (swatch term-এ থাকলে হেক্স কালার)।

GET /group/products-এর সাথে কীভাবে ব্যবহার করবেন

filter_key ফিল্ড বলে দেয় ঠিক কোন query parameter /group/products-এ যোগ করতে হবে। ভ্যালু হিসেবে এক বা একাধিক slug (কমা দিয়ে আলাদা করে) পাঠান।

GET /group/products?{filter_key}={slug1},{slug2}

curl "https://herlan.com/wp-json/herlan/v1/group/products?context_taxonomy=brand&context_term=nior&filter_skin-type=oily-skin"

GET /search

প্রোডাক্ট সার্চ endpoint, ওয়েবসাইটের লাইভ অটোকমপ্লিটের মতো একই ইঞ্জিন দ্বারা চালিত (Ajax Search for WooCommerce / FiboSearch)। পরিষ্কার JSON প্রোডাক্ট কার্ড রিটার্ন করে — কোনো HTML রেন্ডারিং নেই। মোবাইল সার্চ রেজাল্ট স্ক্রিনের জন্য এটা ব্যবহার করুন।
