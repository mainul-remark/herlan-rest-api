Herlan REST API Documentation

Mobile application API for auth, account management, orders, loyalty program, product details, and payment placeholders.

Base URL Response Format Authentication Status Promo Bar Header Config Image Popup Auth User Account Loyalty Coupons Orders Product Filters Products Recommendations Linked Products Navigation Wishlist Payments Auth Error Codes Route Inventory

Base URL

Local development:

http://localhost/herlanlive3/wp-json/herlan/v1

Production:

https://YOUR_DOMAIN/wp-json/herlan/v1

Response Format

Successful responses use this wrapper:

{
  "success": true,
  "message": "",
  "data": {}
}

WordPress REST errors use this wrapper:

{
  "code": "herlan_error_code",
  "message": "Error message.",
  "data": {
    "status": 400
  }
}

Authentication

Protected endpoints require this header:

Authorization: Bearer USER_ID_BASE64.SECRET

Tokens are issued by login/register and expire after 30 days.

Public endpoints: GET /status, GET /promo-bar, GET /header-config, GET /image-popup, POST /auth/login, POST /auth/register, GET /products/{id}, GET /products/filters, GET /drawer-brands-categories.

Protected endpoints: POST /auth/logout, GET /user/me, PUT/PATCH /user/account, GET /user/loyalty, GET /user/coupons, GET /orders, GET /orders/{id}, GET /wishlist, POST /wishlist, DELETE /wishlist/{product_id}, GET /payments/methods, POST /payments/create.

Protected endpoint auth errors: herlan_missing_token, herlan_invalid_token, herlan_expired_token.

  }
}

Promo Bar

GET /promo-bar

Returns the site-wide promotional top bar configuration saved under Herlan Settings -> Top Bar Promo. Mobile apps use this to decide whether to show the banner and what content to display.

This endpoint is public.

curl "http://localhost/herlanlive3/wp-json/herlan/v1/promo-bar"
{
  "success": true,
  "message": "",
  "data": {
    "enabled": true,
    "bg_color": "#D50032",
    "text": "
Free shipping on orders over ৳999!
"
  }
}
{
  "success": true,
  "message": "",
  "data": {
    "enabled": false,
    "bg_color": "#333333",
    "text": ""
  }
}
FieldTypeNotes
enabledbooleanWhether the promo bar is turned on in admin settings
bg_colorstringHex background color for the bar, e.g. #D50032
textstringSanitized HTML content to display inside the bar

When enabled is false, hide the bar entirely regardless of text or bg_color values.

Header Config

GET /header-config

Returns the header appearance settings saved under Herlan Settings -> Header. Mobile apps use this to theme the app header colors and optionally display decorative ornament images.

This endpoint is public.

curl "http://localhost/herlanlive3/wp-json/herlan/v1/header-config"
{
  "success": true,
  "message": "",
  "data": {
    "top_bar": {
      "bg_color": "#ffffff",
      "text_color": "#000000"
    },
    "nav": {
      "bg_color": "#ffffff",
      "text_color": "#000000"
    },
    "mini_cart_badge_color": "#D50032",
    "ornaments": {
      "enabled": true,
      "left": "https://herlan.com/wp-content/uploads/ornament-left.png",
      "right": "https://herlan.com/wp-content/uploads/ornament-right.png"
    }
  }
}
FieldTypeNotes
top_bar.bg_colorstringHex background color for the top bar
top_bar.text_colorstringHex text color for the top bar
nav.bg_colorstringHex background color for the navigation bar
nav.text_colorstringHex text color for the navigation bar
mini_cart_badge_colorstringHex background color for the cart item count badge
ornaments.enabledbooleanWhether header ornament images are active
ornaments.leftstringURL of the left ornament image, empty string if not set
ornaments.rightstringURL of the right ornament image, empty string if not set

When ornaments.enabled is false, ignore the left and right image URLs.

Image Popup

GET /image-popup

Returns the image popup configuration saved under Herlan Settings -> Image Popup. Mobile apps use this to decide whether to display a promotional popup, when to show it again, and which image to use.

This endpoint is public.

curl "http://localhost/herlanlive3/wp-json/herlan/v1/image-popup"
{
  "success": true,
  "message": "",
  "data": {
    "enabled": true,
    "display_location": "all",
    "show_again_after": {
      "hours": 24,
      "minutes": 0,
      "seconds": 0
    },
    "image": "https://herlan.com/wp-content/uploads/popup-desktop.jpg",
    "mobile": {
      "enabled": true,
      "image": "https://herlan.com/wp-content/uploads/popup-mobile.jpg"
    },
    "cta_url": "https://herlan.com/shop/"
  }
}
FieldTypeNotes
enabledbooleanWhether the popup is active
display_locationstringall for all pages, checkout for checkout only
show_again_after.hoursintegerHours before the popup is shown again
show_again_after.minutesintegerAdditional minutes
show_again_after.secondsintegerAdditional seconds. All three at 0 means show on every page load
imagestring|nullDesktop popup image URL, null if not set
mobile.enabledbooleanWhether a separate mobile image is configured
mobile.imagestring|nullMobile popup image URL, null if not set
cta_urlstring|nullURL to open when the popup image is tapped, null if not set

Mobile image logic: if mobile.enabled is true and mobile.image is not null, use mobile.image on mobile devices. Otherwise fall back to image.

Show again timer: store the timestamp when the popup was last shown locally on the device and compare it against the total interval (hours × 3600 + minutes × 60 + seconds) to decide whether to show the popup again.

Auth

POST /auth/login

Login with WordPress username/email and password. Returns a bearer token.

{
  "username": "customer@example.com",
  "password": "password123",
  "device_name": "iPhone 15"
}
{
  "success": true,
  "message": "",
  "data": {
    "token_type": "Bearer",
    "access_token": "MQ.example_token_secret",
    "expires_at": "2026-05-30T06:00:00+00:00",
    "user": {
      "id": 1,
      "name": "Customer Name",
      "first_name": "Customer",
      "last_name": "Name",
      "email": "customer@example.com",
      "username": "customer@example.com",
      "roles": ["customer"]
    }
  }
}

Errors: 401 herlan_invalid_credentials

POST /auth/register

Creates a WordPress user and returns a mobile token. WordPress registration must be enabled. Response shape is identical to login.

{
  "name": "Customer Name",
  "email": "customer@example.com",
  "password": "password123"
}

Errors: 403 herlan_registration_disabled   409 herlan_email_exists   422 herlan_invalid_email   422 herlan_weak_password

POST /auth/logout

Revokes the current bearer token.

curl -X POST "http://localhost/herlanlive3/wp-json/herlan/v1/auth/logout" \
  -H "Authorization: Bearer MQ.example_token_secret"

Account

PUT PATCH /user/account

Updates the authenticated user's profile. All fields are optional — only send what needs to change. Changing email or new_password requires current_password.

FieldTypeNotes
first_namestringNo password required
last_namestringNo password required
display_namestringNo password required
emailstringRequires current_password
current_passwordstringRequired when changing email or password
new_passwordstringMin 8 characters. Requires current_password

Update name

curl -X PATCH "http://localhost/herlanlive3/wp-json/herlan/v1/user/account" \
  -H "Authorization: Bearer MQ.example_token_secret" \
  -H "Content-Type: application/json" \
  -d "{\"first_name\":\"Jane\",\"last_name\":\"Doe\"}"

Change password

curl -X PATCH "http://localhost/herlanlive3/wp-json/herlan/v1/user/account" \
  -H "Authorization: Bearer MQ.example_token_secret" \
  -H "Content-Type: application/json" \
  -d "{\"current_password\":\"oldpass123\",\"new_password\":\"newpass456\"}"

Response

{
  "success": true,
  "message": "Account updated successfully.",
  "data": {
    "user": {
      "id": 1,
      "name": "Jane Doe",
      "first_name": "Jane",
      "last_name": "Doe",
      "email": "customer@example.com",
      "username": "customer@example.com",
      "roles": ["customer"]
    }
  }
}

Errors: 401 herlan_invalid_password   409 herlan_email_exists   422 herlan_password_required   422 herlan_invalid_email   422 herlan_weak_password

Product Filters

GET /products/filters

Returns mobile filter metadata for shop and taxonomy pages. Use taxonomy and term for category, brand, keyword, or attribute archive context. Results are cached for 10 minutes. Public endpoint.

curl "http://localhost/herlanlive3/wp-json/herlan/v1/products/filters"

curl "http://localhost/herlanlive3/wp-json/herlan/v1/products/filters?taxonomy=product_cat&term=makeup"

curl "http://localhost/herlanlive3/wp-json/herlan/v1/products/filters?taxonomy=brand&term=herlan"

The response includes sort_options, price_range, and filters. Filters include product_cat, brand, product_tag, keywords, and pa_* product attributes.
